# ChatWindow 工具调用使用指南

## 🎯 功能概述

ChatWindow 现在支持 **LLM 工具调用（Tool Calling）**，让 AI 助手可以主动操作 WhatNote 系统，包括：
- 📝 创建、编辑、删除窗口
- 📚 创建课程和展板
- 📅 管理日历任务
- 🔍 搜索内容

---

## 🚀 快速开始

### 1. 打开聊天窗口

在任意展板上，点击右键 → 选择"聊天窗口"

### 2. 启用工具调用

在聊天窗口顶部工具栏，找到 **🔧 工具** 按钮：
- ✅ **蓝色高亮** = 已启用（默认）
- ⚪ **灰色** = 已禁用

点击按钮可以切换状态。

### 3. 开始对话

直接用自然语言与 AI 对话，AI 会根据需要自动调用工具。

## 🤖 AI 如何调用工具？

### 不是文本指令

AI **不会**像控制台那样输入命令：
```
❌ 不是这样：list_tasks 2025-11-04
```

### 而是结构化调用

AI 通过 JSON 格式的函数调用：
```json
✅ 是这样：
{
  "name": "list_tasks",
  "arguments": {
    "date": "2025-11-04"
  }
}
```

**这意味着**：
- 您只需用自然语言对话
- AI 会自动判断是否需要调用工具
- AI 会自动选择合适的工具
- AI 会自动填充参数

## ⚙️ 工具调用开关

### 何时启用？ ✅

**适用场景**：
- 需要 AI 主动操作系统（创建、编辑、查询）
- 需要多步骤自动化（如批量创建任务）
- 需要智能搜索和整理

**优势**：
- AI 更强大，可以实际操作系统
- 可以完成复杂的多步骤任务
- 更加自动化和智能

### 何时禁用？ ⚪

**适用场景**：
- 只想纯粹对话（问答、讨论）
- 不想 AI 修改数据
- 测试或学习阶段

**优势**：
- AI 响应更快（无工具调用开销）
- 更加可控和安全
- 适合纯对话场景

## 🔄 工作流程详解

### 完整流程

```
1. 用户发送消息
   ↓
2. 后端将消息和工具定义发送给 LLM
   ↓
3. LLM 分析并决定是否调用工具
   ↓ (如果需要)
4. LLM 返回 tool_calls (JSON 格式)
   ↓
5. 后端执行工具
   ↓
6. 工具返回结果
   ↓
7. 结果添加到对话上下文
   ↓
8. LLM 基于结果生成自然语言回复
   ↓
9. 前端显示完整过程
```

### 多轮调用

如果任务需要多个工具：
```
轮1: 用户消息 → LLM 调用 create_course
     ↓ 返回课程ID
轮2: LLM 调用 create_board（监督学习）
     ↓ 返回展板ID
轮3: LLM 调用 create_board（无监督学习）
     ↓ 返回展板ID
轮4: LLM 调用 create_board（强化学习）
     ↓ 返回展板ID
轮5: LLM 生成最终回复
```

**限制**：最多 5 轮调用，防止无限循环

## 💡 使用技巧

### 1. 清晰表达意图

✅ **好的提问**：
```
帮我查看今天有什么任务
创建一个Python学习笔记
规划明天的学习计划
```

❌ **不好的提问**：
```
任务（太模糊）
笔记（不知道要做什么）
```

### 2. 提供必要信息

✅ **包含关键信息**：
```
帮我创建一个"机器学习"课程，包含3个章节：...
明天早上9点提醒我复习
```

❌ **信息不足**：
```
创建一个课程（没说名字和内容）
提醒我（没说时间和内容）
```

### 3. 自然对话

您可以像和人对话一样：
```
"我想整理一下笔记，能帮我搜索所有关于Python的窗口吗？"
"明天我有个会议，帮我在日历里加个提醒"
"这个窗口的内容有点乱，能帮我重新组织一下吗？"
```

### 4. 利用上下文

AI 会记住对话历史：
```
用户: "帮我创建一个机器学习课程"
AI: [创建完成] "已创建课程'机器学习'"

用户: "在这个课程下创建监督学习章节"
AI: [自动知道是哪个课程] "已创建..."
```

### 5. 验证结果

工具调用后，可以：
- 在展板上查看新创建的窗口
- 在日历中查看新添加的任务
- 在课程列表中查看新课程

## ⚠️ 注意事项

### 1. API 配置

工具调用需要配置支持的 LLM API：
- ✅ **通义千问（qwen-plus）** - 推荐
- ✅ OpenAI (gpt-4)
- ✅ Anthropic (claude-3.5-sonnet)
- ❌ **qwen-vl-max** - 视觉模型，工具调用支持不完整

### 2. 数据安全

工具调用会实际修改数据：
- 创建的窗口/任务/课程会保存
- 删除操作（默认移到回收站）
- 编辑操作会覆盖原内容

**建议**：
- 重要操作前备份数据
- 测试时使用测试展板
- 删除前确认

### 3. 性能考虑

工具调用比纯对话慢：
- 需要额外的 API 调用轮次
- 工具执行需要时间
- 多轮调用累积延迟

**如果只需要对话**，关闭工具调用可以更快。

### 4. 限制

- **最大轮数**：5 轮工具调用
- **超时**：单个工具 30 秒
- **并发**：一次只处理一个工具调用（截断机制）

## 🐛 故障排查

### 问题 1：工具调用无响应

**症状**：AI 说要调用工具，但没有实际执行

**原因**：
- 使用了不支持工具调用的模型（如 qwen-vl-max）
- API 配置错误

**解决**：
1. 打开设置，检查当前模型
2. 切换到 `qwen-plus` 或 `gpt-4`
3. 保存配置并重试

---

### 问题 2：工具调用失败

**症状**：看到 `❌ 工具执行失败` 错误

**原因**：
- 参数验证失败（如缺少必需参数）
- 工具执行异常（如文件不存在）

**解决**：
1. 查看错误信息
2. 提供更完整的信息重试
3. 检查控制台日志

---

### 问题 3：AI 不使用工具

**症状**：AI 只回答不操作

**原因**：
- 工具调用开关未启用
- 提问方式不明确

**解决**：
1. 检查工具栏中的 🔧 按钮是否蓝色高亮
2. 更明确地表达意图："帮我创建..."而不是"我想要..."

---

### 问题 4：达到最大调用次数

**症状**：看到 `⚠️ 已达到最大工具调用次数 (5)`

**原因**：
- 任务太复杂，需要太多步骤
- LLM 陷入循环调用

**解决**：
1. 将复杂任务分解为多个简单请求
2. 提供更明确的指令
3. 检查是否有逻辑错误
