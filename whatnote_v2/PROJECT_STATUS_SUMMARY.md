# WhatNote V2 项目状态总结

## 📋 项目概览

WhatNote V2 是一个基于 **FastAPI + React + Electron** 的智能笔记管理系统，具有类似Windows 98风格的桌面界面。核心特色是**基于真实文件系统的存储架构**（非JSON模拟）、**多模态LLM聊天功能**，以及**完整的PDF智能批量注释系统**。

## 🏗️ 技术架构

### 后端 (FastAPI)
- **主要文件**: `backend/main.py` - 核心API服务器
- **端口**: 8081
- **存储管理器**:
  - `FileSystemManager` - 文件系统操作
  - `ContentManager` - 内容管理
  - `ConversationManager` - LLM对话管理
  - `APIConfigManager` - 全局API配置管理
- **服务模块**:
  - `LLMService` - 多服务商LLM API调用
  - `FileWatcher` - 文件变化监控
  - `DocumentConverter` - 文档转换（PDF、Word等）

### 前端 (React + Electron)
- **主要组件**:
  - `App.js` - 主应用，包含任务栏和课程管理
  - `BoardCanvas.js` - 展板画布，统一窗口管理系统（8500+行）
  - `ChatWindow.js` - LLM聊天窗口（支持多模态、流式响应）
  - `RadialMindMap.js` - 思维导图组件（全自研，无外部依赖）
  - `Header.js`, `Sidebar.js` - 界面组件
- **端口**: 3000/3001 (开发模式)

## 💾 存储架构详解

### 🎯 核心理念：真实文件系统存储
**不是JSON模拟**，而是基于真实的文件和文件夹结构：

```
whatnote_data/
├── api_config.json                    # 全局LLM API配置
├── courses/                           # 课程根目录
│   ├── course-1756987907632/         # 课程文件夹（时间戳ID）
│   │   ├── course_info.json          # 课程元数据
│   │   └── board-1756987954946/      # 展板文件夹（时间戳ID）
│   │       ├── board_info.json       # 展板元数据
│   │       ├── windows.json          # 窗口状态（位置、大小、层级）
│   │       ├── icon-positions.json   # 桌面图标位置
│   │       ├── files/                # 用户文件存储
│   │       │   ├── images/           # 图片文件
│   │       │   ├── videos/           # 视频文件
│   │       │   ├── audios/           # 音频文件
│   │       │   ├── pdfs/             # PDF文件
│   │       │   ├── texts/            # 文本文件
│   │       │   └── pages/            # PDF分页提取内容
│   │       │       └── document.pdf/ # PDF文件名为目录
│   │       │           ├── PDF_page_001.md  # 第1页文字提取
│   │       │           ├── PDF_note_001.md  # 第1页注释内容
│   │       │           ├── outline.json     # PDF大纲数据
│   │       │           └── subdivisions.json # 分段细分数据
│   │       └── llm_conversations/    # LLM对话记录
│   │           ├── conv-xxx.json     # AI助手主对话（每个展板独立）
│   │           └── message-center.json # 消息中心记录
│   └── course-yyy/                   # 其他课程
└── trash/                            # 回收站
    ├── deleted_files...
    └── trash_info.json
```

### 🔑 存储特点

1. **层次化结构**: 课程 → 展板 → 文件/窗口/对话
2. **时间戳ID**: 所有实体使用时间戳作为唯一标识
3. **元数据分离**: 每个实体都有对应的JSON配置文件
4. **文件类型分类**: 自动按类型组织文件到不同子目录
5. **状态持久化**: 窗口位置、图标位置等UI状态实时保存
6. **智能存储**: PDF相关数据集中存储在 `pages/` 目录

## 🤖 LLM聊天功能

### 功能特性
- **多服务商支持**: OpenAI、Anthropic、Gemini、Qwen（通义千问）
- **全局配置**: API配置存储在比课程更高级别，所有展板共享
- **流式响应**: 支持打字机效果的实时回复，带流式输出指示器
- **多模态支持**: 可发送展板中的图片、音频、视频、PDF文件
- **对话持久化**: 每个展板独立的对话记录
- **Markdown渲染**: 完整支持粗体、斜体、代码、表格等格式
- **Mermaid图表**: 支持流程图、时序图、甘特图等图表渲染
- **LaTeX公式**: 支持数学公式渲染（行内和块级）
- **系统通知**: 批量操作自动添加系统消息到AI助手上下文

### 技术实现
- **后端**: `LLMService` 处理不同服务商的API格式差异，支持OpenAI兼容模式
- **前端**: 集成在统一窗口管理系统中，支持拖拽、缩放
- **存储**: 对话记录存储在 `llm_conversations/` 目录
- **配置**: 全局API配置存储在 `api_config.json`
- **渲染**: 使用ReactMarkdown + remarkGfm + remarkMath + rehypeKatex
- **图表**: 集成Mermaid.js支持多种图表类型
- **流式输出**: 基于Server-Sent Events (SSE) 实现实时响应

### API端点
- `GET /api/llm/config` - 获取API配置
- `POST /api/llm/config/{provider}` - 更新服务商配置
- `POST /api/llm/provider/{provider}` - 设置当前服务商
- `POST /api/llm/chat` - 流式对话API

## 📝 PDF智能批量注释系统（核心功能）

### 系统架构

```
PDF上传
  ↓
自动分页提取文字
  ↓
┌─────────────────────────────────────────┐
│  阶段1: 大纲生成（LLM分析全文）         │
│  - 输入：所有页面文字内容               │
│  - 输出：分段大纲（JSON结构）           │
│  - 存储：outline.json                   │
└─────────────────────────────────────────┘
  ↓
┌─────────────────────────────────────────┐
│  阶段2: 分段细分（并行处理）            │
│  - 输入：每个分段的页面内容             │
│  - 输出：子分段结构 + 部分列表          │
│  - 存储：subdivisions.json              │
└─────────────────────────────────────────┘
  ↓
┌─────────────────────────────────────────┐
│  阶段3: 逐页注释生成（并行）            │
│  - 输入：页面内容 + 上下文信息          │
│  - 输出：每页的Markdown注释             │
│  - 存储：PDF_note_001.md                │
└─────────────────────────────────────────┘
  ↓
┌─────────────────────────────────────────┐
│  阶段4: 重叠页融合（如有重叠）          │
│  - 检测：跨分段的重叠页面               │
│  - 融合：合并多个注释为完整内容         │
│  - 更新：覆盖原注释文件                 │
└─────────────────────────────────────────┘
  ↓
完整的PDF注释系统
```

### 核心功能

#### 1. PDF分页和文字提取
- **自动分页**: PDF上传后自动按页提取文字内容
- **存储位置**: `files/pages/PDF文件名/PDF_page_001.md`
- **内容包含**: 页码、来源、提取时间、纯文字内容
- **性能优化**: 并行处理多页提取

#### 2. 三级大纲侧栏系统
- **位置**: PDF分页模式右侧，可调节宽度（默认320px，思维导图模式60%）
- **三种视图模式**:
  - **📋 列表视图**: 传统树形结构，显示分段和细分
  - **📖 详情视图**: 点击分段查看完整细分信息
  - **🌐 思维导图**: 圆形放射状结构，可视化文档层次

#### 3. 思维导图功能（全自研）
- **无外部依赖**: 完全自主实现，未使用任何图表库
- **圆形放射状布局**:
  ```
  中心：文件名（蓝色矩形）
    ↓
  内圈：分段列表（绿色圆角矩形）
    ↓
  中圈：细分列表（紫色圆角矩形）
    ↓
  外圈：页码列表（白色圆形）
  ```
- **交互功能**:
  - 🖱️ 中键拖拽：移动画布
  - 🎡 滚轮缩放：以鼠标位置为中心缩放
  - 👆 点击节点：跳转到对应PDF页面
  - 🎨 悬停高亮：黄色高亮显示
- **可定制性**:
  - 📊 层级控制：选择显示1-4级结构
  - 📏 半径调节：手动/自动模式切换
  - 🎯 防重叠算法：自动计算最优节点间距
  - ⚙️ 实时预览：所有调整立即生效

#### 4. 批量注释生成
- **阶段1 - 大纲生成**:
  - LLM分析整个PDF文字内容
  - 生成结构化分段大纲（章节、页码范围、描述）
  - 检测大纲变化，提供自定义确认对话框
  - 存储为 `outline.json`

- **阶段2 - 分段细分**:
  - 并行处理每个分段
  - 生成子分段和部分列表
  - 实时显示进度条（Windows 98风格量子化方格）
  - 存储为 `subdivisions.json`

- **阶段3 - 注释生成**:
  - 并行生成所有分段的逐页注释
  - 支持多种注释风格（详细、简洁、学术、问答）
  - 实时进度反馈
  - 自动添加系统通知到AI助手

- **阶段4 - 重叠页融合**:
  - 检测跨分段的重叠页面
  - 使用LLM融合多个注释
  - 生成完整统一的注释内容
  - 自动更新注释文件

#### 5. 注释存储系统
- **存储位置**: `files/pages/PDF文件名/PDF_note_001.md`
- **存储内容**: 纯Markdown内容（无元数据污染）
- **文件信息**: 使用文件系统的真实创建/修改时间
- **自动保存**: 1秒防抖自动保存机制
- **版本控制**: 通过文件修改时间追踪

#### 6. 智能上下文系统
- **系统消息**: 批量操作自动生成系统消息
- **可点击跳转**: 消息中可点击跳转到对应PDF页面或大纲
- **上下文感知**: LLM知道最近用户操作的文件和内容
- **消息类型**:
  - 📋 大纲生成通知
  - 📝 分段注释生成通知
  - ✅ 批量处理完成通知
